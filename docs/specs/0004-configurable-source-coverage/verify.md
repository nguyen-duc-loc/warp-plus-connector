# Configurable source coverage verification

Status: planned. These scenarios have not been executed. Use the real CLI and store after implementation. Keep live keys and raw source HTML out of evidence files.

1. With no source settings, inspect all four enabled defaults and crawl one page each in the saved order. With a custom config, prove replacement, disabled entries, case normalization, shared and per source limits, explicit flag precedence, and subset selection. Reject invalid, duplicate, unknown, disabled, empty, and excessive inputs before state or network access. Covers AC-1, AC-2, AC-3.
2. Prove `sources`, command help, and version with instrumented state and network boundaries. Only `sources` reads configuration. Include an empty source list and a missing state directory. Covers AC-2, AC-3, AC-10.
3. Use a controlled source transport and the real store to observe committed source plans before the first request and request intent before each page. Confirm first request intent time equals source start time. Kill the process at each boundary, including parsed facts before messages and midway through message saving. Restart and inspect the report before and after writer recovery. Assert `interrupted` for active page, source, and parent reasons, `interrupted_before_start` for pending sources, recovery timestamps without invented finish times, and preservation of terminal children. Covers AC-4, AC-8, AC-10.
4. Use at least two channels and two pages with repeated candidates, repeated posts across pages, case distinct keys, media posts, and posts without keys. Verify candidate and sighting identities, first page attribution, exact saved counts, parsed occurrence counts, and unchanged definitive evidence across repeated crawls. Covers AC-4, AC-6, AC-9.
5. Exercise recognized empty feeds, missing older controls, valid relative and absolute controls, conflicting cursor attributes, foreign origins, altered paths, duplicate query parameters, invalid IDs, nonprogressing cursors, malformed feed content, and duplicate IDs within a page. Count requests to prove no extra probe at the page budget. Covers AC-5, AC-9.
6. Measure request start times with an injected monotonic timer. Prove one second spacing across channel boundaries, cancellation during waits, the per request deadline, decoded compressed body overflow, redirect rejection, and no HTTP replay. Covers AC-5, AC-8.
7. Inject an ordinary failure on a later page, then a successful later channel. Inspect preserved earlier commits and exit 1. Separately inject HTTP 429 and prove no subsequent request, truthful skipped sources, and retained results. Simulate mutation failure before commit, after commit with a lost acknowledgement, and during terminal writes. Assert no subsequent mutation or HTTP request and preserve the original CLI error. Prove that a failed message write prevents page completion and another page request. Separately exercise safe cleanup after a nonmutating state failure: active children and parent use the classified state code, pending sources use `state_abort`. If cleanup fails, stop further writes. Covers AC-7, AC-8.
8. Create a version 2 database containing candidates, provenance, validation evidence, and both covered and legacy crawl runs. Upgrade, compare all existing records, and read both report formats. Force migration rollback. Check new schema rejection by an older binary and writer contention before HTTP. Covers AC-10.
9. Change or remove source configuration after a run. Inspect its complete saved plan and every page, including active progress and unknown facts. Test output failure and signal exit codes without corrupting saved outcomes. Scan stdout, stderr, and evidence for accidental key values or raw content. Covers AC-3, AC-4, AC-8, AC-9, AC-10.
10. Verify live normalized channel identity and at least two public preview pages on a reachable configured source, recording only counts, ID bounds, cursors, status, and timestamps. Preserve a sanitized fixture that proves the navigation grammar. Do not require a fixed candidate yield or trigger entitlement checks. If live pagination cannot be established, record the unmet criterion rather than declaring this slice complete. Covers AC-1, AC-5, AC-9.
11. Run the repository formatting, vet, race, and lint gate. Exercise migration, recovery, and CLI behavior on macOS and Linux arm64. After behavior verification, retain meaningful regression tests through `/test`. Covers AC-1 through AC-10.
